# WearBridgeADB

[English](README.en.md) · Русский

Локальный Android/Wear OS проект для выполнения команд часов через Shizuku и Wear OS Data Layer. **Приложение не анализирует безопасность команд:** оно выполняет введённые пользователем команды на часах, поэтому перед запуском важно проверить их текст, режим и профиль доступа. Телефон и часы должны быть сопряжены в приложении Wear OS. Команды передаются через Wear Data Layer; ADB TCP порт и внешний сетевой shell не открываются. Опциональный Termux API слушает только `127.0.0.1` и требует приватный bearer token.

## Важно: команды выполняются напрямую

Пользователь сам выбирает NORMAL или STREAM и профиль SHELL или ROOT. Команды могут удалять или изменять файлы, останавливать службы и менять настройки часов. В ROOT команда выполняется с root-полномочиями; приложение не изолирует команды и не предупреждает об их возможных последствиях. Перед запуском проверяйте команду, режим и профиль доступа; не запускайте команды из непроверенных источников.

Телефонный Termux API также даёт доступ к выполнению команд через секретный bearer token. Держите токен в секрете и включайте API только на время использования. API привязан к `127.0.0.1`, но другие локальные процессы на телефоне с токеном могут им пользоваться.

## Состояние реализации

- Текущие версии APK: Phone 1.45 и Wear 1.33. В телефонной шапке показывается имя подключённых часов; доступны Terminal / Files / Settings и ручной выбор языка. Полноэкранный STREAM использует собственный `BridgeTerminalView` поверх активного Wear Channel; размеры терминала передаются в PTY часов через `TIOCSWINSZ`.

- NORMAL — команда отправляется MessageClient и выполняется через Shizuku UserService; на экране показывается только фактический вывод команды без эха `$ команда`, request ID и служебных меток stdout/stderr/exit code. Классификации команд нет: `logcat` остаётся обычной командой и не переключает режим.
- STREAM — ручное включение открывает ChannelClient и одну интерактивную `/system/bin/sh -i` с настоящим PTY. Native PTY собирается для arm64 и armeabi-v7a (часы могут запускать 32-битные процессы на 64-битном SoC); line discipline передаёт Ctrl+C/Z/D/\\, Enter, Tab и ANSI стрелки. Закрытие канала завершает именно shell-сессию.
- На телефоне есть кнопки управляющих байтов и физические клавиши для Ctrl+C/D/Z/\, Esc, Tab, стрелок и Enter. Полноэкранный `BridgeTerminalView` обрабатывает ввод через Android IME, основные ANSI CSI команды, курсор, прокрутку и выделение долгим нажатием. Это пока не полная реализация VT/xterm; сложные полноэкранные программы требуют отдельной проверки.
- На телефоне профиль выполнения выбирается вручную: SHELL или ROOT. Часы получили root через jailbreak пользователя; разрешение приложению выдаётся в KernelSU. SHELL выполняется через Shizuku UserService. ROOT запускает только виртуальный `/system/bin/su` из UID самого WearBridgeADB приложения на часах: KernelSU sucompat перехватывает этот точный путь для разрешённого UID. `/system/xbin/su` не используется. Если KernelSU не разрешает этот путь, Wear v6 выводит UID приложения и диагностическое сообщение. SHELL использует текущий UID Shizuku, поэтому если сам Shizuku запущен как root, даже профиль SHELL останется UID 0.
- Кнопка **TERMUX API** включает/выключает HTTP API только на loopback телефона (`127.0.0.1:18765`). Bearer token хранится в private app files; включайте API только на время использования.
- На часах отображается доступность Shizuku, permission и UID; `Test id` вызывает UserService. При запуске Shizuku через ADB ожидается `uid=2000(shell)`, через root backend — UID 0.
- Пока STREAM PTY открыт, watch service удерживается foreground notification и частичным `PARTIAL_WAKE_LOCK`; lock отпускается при закрытии сессии. В настройках часов есть ручной запрос исключения приложения из оптимизации батареи и отображение статуса. Это снижает шанс остановки CPU во время сессии, но Android/Wear OS всё равно могут ограничить сеть или завершить приложение; гарантированного запрета Doze нет.
- В файловом браузере выберите один APK и откройте **⋮ → Install selected APK** либо нажмите **Install** на нижней панели выделения. Установка выполняется через Shizuku SHELL. В локальном API доступна команда `./scripts/wadb install /sdcard/Download/app.apk`.
- На Xiaomi Watch 5 ранее проверен живой resize PTY: `stty size` меняется при появлении клавиатуры и повороте экрана. Wear 1.17 добавил доставку `/terminal/resize`; в 1.18 добавлены настройки питания для активного STREAM.

## Toolchain и сборка в Termux

Gradle-проект находится в `source/WearBridgeADB`. Локальная сборка рассчитана на Termux с установленными JDK, Android SDK и clang:

```sh
cd ~/wearbrdgeadb
./build.sh all       # либо phone / wear
./sign.sh all        # либо phone / wear
./rebuild-all.sh     # сборка двух APK и подпись
```

Результаты:

- `phone/output/wearbridgeadb-phone.apk`
- `wear/output/wearbridgeadb-wear.apk`

Подпись сделана через локальный `apksigner.jar` и `keys/wearbridge-project.p12`. Пароль находится в `keys/signing.env` (режим файла 600); не публикуйте этот файл или keystore. Оба APK прошли `apksigner verify`; SHA-256 сертификата: `ffaf5095b044803a5c90c33aedec9e5883028ccd73e5f536b217b3cb98a22ade`.

## GitHub Actions

`.github/workflows/android-build.yml` собирает phone и Wear debug APK на push в `main`, pull request и по ручному запуску. Результаты доступны как workflow artifacts в GitHub Actions в течение 14 дней. CI использует временный Android debug key; эти APK предназначены для проверки сборки и не обновляют установленную локально подписанную версию без удаления приложения. Keystore и пароль локальной подписи в репозиторий не входят.

## Установка и первый запуск

1. Установите Shizuku на часы и запустите его через Wireless Debugging / Wireless ADB. Это отдельное приложение, APK Shizuku проект не заменяет.
2. Установите `wear/output/wearbridgeadb-wear.apk` на часы и `phone/output/wearbridgeadb-phone.apk` на телефон. Пример с ADB serial:

```sh
./install.sh wear WATCH_ADB_SERIAL
./install.sh phone PHONE_ADB_SERIAL
```

3. Откройте WearBridgeADB на часах, нажмите **Request Shizuku permission**, подтвердите разрешение в Shizuku, затем нажмите **Test id**. Проверьте строку `uid=2000(shell)`.
4. Откройте приложение на телефоне. Статус должен показать обнаруженные часы. Выберите NORMAL или STREAM вручную. Профиль ROOT тоже включается вручную; при необходимости подтвердите root grant на часах.

## Termux API

1. Запустите WearBridgeADB на телефоне и нажмите **TERMUX API · OFF**, чтобы включить локальный API. Android покажет постоянное уведомление, пока API работает.
2. В Termux установите `curl` (`pkg install curl`) и запустите клиент из папки проекта:

```sh
./scripts/wadb status
./scripts/wadb --root id
./scripts/wadb --root 'getprop ro.build.fingerprint'
./scripts/wadb --shell 'dumpsys battery'
./scripts/wadb --shell --normal 'logcat -d'
./scripts/wadb --shell --stream
```

Чтобы настроить Bearer-токен: в WearBridge на телефоне включите **TERMUX API** и нажмите **Copy API token**. В Termux из корня проекта выполните `./scripts/wadb configure`; вставьте скопированный токен в скрытый запрос ввода и нажмите Enter. `wadb` сохранит его в `~/.config/wearbridgeadb/token` с правами доступа только владельцу. Не отправляйте токен в чат, не добавляйте его в командную строку и не публикуйте. Root на телефоне и Termux:API plugin не нужны. `WADB_TOKEN` можно задать через окружение вместо файла. Профиль `--root` относится только к часам и требует разрешённого root backend на часах. `--normal` выполняет одну команду (это значение по умолчанию); `--stream` вручную открывает постоянную интерактивную PTY-сессию, при желании с начальной командой. Режим не выбирается по имени команды: даже `logcat` выполняется ровно в указанном режиме. В CLI STREAM клавиши Ctrl+C/D/Z и стрелки передаются PTY; Ctrl+] закрывает клиент и удалённую сессию. Команды идут через Wear Data Layer независимо от выбора файлового транспорта. Файловые `push/pull` используют Data Layer по умолчанию, а `--wifi` явно включает Wi-Fi для байтов файла. Примеры:

```sh
./scripts/wadb --shell --normal 'id'
./scripts/wadb --root --stream 'logcat'
./scripts/wadb --shell --wifi push ./app.apk /sdcard/Download/app.apk
./scripts/wadb --shell --datalayer pull /sdcard/Download/log.txt ./log.txt
```

Одиночные запросы используют `/v1/exec`, а STREAM открывает ChannelClient только на время активной PTY-сессии. Размер команды ограничен 65536 байт UTF-8. Команда `./scripts/wadb install /sdcard/Download/app.apk` устанавливает APK на часах через Shizuku SHELL независимо от выбранного ROOT-профиля. Остановите API той же кнопкой после работы. Для NORMAL клиент печатает requestId перед запуском; Ctrl+C отправляет часам запрос отмены. Если клиент прерван отдельно, выполните ./scripts/wadb cancel REQUEST_ID. Для --async используйте ./scripts/wadb job cancel JOB_ID. Статус async-job содержит `stage` и `lastActivityAt` помимо `updatedAt`: это показывает этап моста и время последнего перехода, но не гарантирует, что команда выдаёт потоковый вывод. Ответ cancel_sent/cancel_requested подтверждает отправку, но не остановку процесса: проверьте итоговый ответ или состояние job. Отмена best-effort и может не остановить потомков shell-команды.

В **Settings → Diagnostics** можно включить локальную трассировку запросов на телефоне и отдельно на часах. Она записывает этапы Data Layer, ожидание ответа, отмену, async-job и состояние питания часов; текст команд не записывается и данные никуда не отправляются. При задержке включите её на обоих устройствах заранее, повторите короткую команду и скопируйте обе трассы. Получение Shizuku UserService на часах теперь выполняется через отдельный single-flight worker; ожидание backend ограничено 15 секундами. Если сам Binder-вызов завис, запрос вернёт ошибку по таймауту, а единственная bind-попытка останется в фоне до завершения — повторные команды не создают очередь bind-вызовов.

API не доступен с Wi-Fi/LAN: сервер привязан только к IPv4 loopback `127.0.0.1`, сервис не экспортирован, запросы требуют случайный bearer token.

## Передача файлов по Wi-Fi

На телефоне нажмите **FILES · DIRECT WI-FI**. Для отправки выберите путь назначения на часах и локальный файл; для скачивания укажите путь на часах и место сохранения на телефоне. Телефон и часы должны быть подключены к одной локальной Wi-Fi сети, а сеть должна разрешать связь между клиентами. В отличие от `ChannelClient`, который предпочитает Bluetooth, крупные данные здесь идут напрямую по Wi-Fi.

Профиль **SHELL / ROOT** выбирается вручную общей кнопкой приложения. ROOT-чтение/запись выполняется через разрешённый KernelSU `/system/bin/su` от UID приложения часов; для ROOT-операции приложение показывает отдельное подтверждение. В SHELL доступны только пути, разрешённые UID приложения. Используются абсолютные пути на часах.

Для каждой передачи часы открывают случайный порт только на Wi-Fi IPv4 адресе и закрывают его после передачи/тайм-аута. Запрос и одноразовый 256-битный ключ приходят по парному Wear Data Layer; TCP-сеанс требует HMAC-аутентификацию, а блоки файла защищены AES-GCM. Открытого shell endpoint нет.

## Проверки

**NORMAL:** выберите NORMAL, выполните `id`, затем `getprop`, `dumpsys battery`, `settings get system screen_off_timeout`. В ответе отображаются exit code/stdout/stderr. Команда `logcat` в NORMAL будет ждать завершения ровно как обычная команда; режим сам не изменится.

**STREAM:** вручную нажмите STREAM ON, введите `id` и RUN/ENTER, затем `cd /data/local/tmp`, `pwd`, `logcat`. Вывод PTY идёт по ChannelClient непрерывно. STOP посылает Ctrl+C; prompt должен остаться активным. Выполните следующую команду. **CLOSE TERMINAL / DISCONNECT** закрывает канал и PTY целиком.

**Wi-Fi-off experiment:** сначала убедитесь, что Shizuku запущен и `id` возвращает shell UID при Wireless Debugging. Затем выключите Wireless Debugging и полностью Wi-Fi на часах, оставив сопряжение Bluetooth активным; повторите `id` в NORMAL и STREAM. Wear Data Layer использует Bluetooth, когда он доступен; файловый режим DIRECT WI-FI требует включённого Wi-Fi и общей локальной сети.

**Файлы часов:** на часах откройте WearBridgeADB и разрешите **Nearby Wi-Fi** (Android 13+) и **shared storage** (профиль SHELL и `/sdcard`). На телефоне разрешите системный запрос **Nearby devices** при первой передаче по локальной сети. Затем нажмите **FILES · DIRECT WI-FI**. Для скачивания откройте папку и нажмите файл; системный Android picker попросит выбрать место на телефоне. Для загрузки выберите файл на телефоне, перейдите в папку часов и нажмите **Upload here**. В браузере можно подниматься на уровень выше, открывать `/` и возвращаться к `/sdcard`; вводить абсолютные пути вручную не нужно. Каталоги и размеры читаются через Wear Data Layer, содержимое передаётся по Wi-Fi между устройствами в общей локальной сети; профиль ROOT запрашивает подтверждение перед доступом.

Для выделения файлов/каталогов зажмите строку или отметьте чекбокс: без перезагрузки списка снизу появится компактная панель со счётчиком, очисткой, скачиванием и удалением. Сортировка, переход в `/` или `/sdcard`, подтверждение удаления и закрытие находятся в меню верхней строки. Позиция прокрутки сохраняется. Можно выбрать сразу несколько элементов, в том числе папки; удаление папки рекурсивное. Подтверждение включено по умолчанию, состояние сохраняется на телефоне. В диалоге подтверждения есть «Do not ask before deleting». Удаление передаётся часам через Wear Data Layer и выполняется в выбранном SHELL/ROOT профиле; корень `/` защищён от удаления.

Полноэкранный терминал STREAM использует собственный код WearBridge. Открытие и закрытие окна и поворот экрана не меняют ручной режим и не закрывают активный удалённый PTY. При изменении высоты экранной клавиатурой текущая строка терминала остаётся видимой. Размер шрифта полноэкранного терминала (12–22 sp, по умолчанию 15 sp) задаётся в Settings; кнопка Clear очищает локальный экран и сохранённый вывод без разрыва PTY. Для передачи размеров PTY установите Wear v17 или новее вместе с Phone v33.
